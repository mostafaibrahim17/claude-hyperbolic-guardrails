## Renting, verifying, and tearing down a GPU through conversation

The whole loop happens in one Claude Code session. What follows is the real run from 10 September 2026, trimmed for length. Budget cap $10, auto-terminate 30 minutes. Hook output on the passing path goes to the ledger rather than the screen, so the ledger lines are quoted where they matter.

### 1. Find something to rent

```
> what H100s are available on hyperbolic right now?

⏺ mcp__hyperbolic-gpu__list-available-gpus(gpu_type: "h100")

⏺ Three H100 options are live right now, all in Canada.
  | GPUs | Region    | Form factor | $/hr  | vCPU / RAM / disk       |
  | 1    | ca-east-1 | PCIe        | 2.75  | 28 / 180 GB / 850 GB    |
  | 1    | ca-east-3 | SXM5        | 4.85  | 20 / 240 GB / 720 GB    |
  | 8    | ca-east-1 | PCIe        | 22.00 | 252 / 1,440 GB / 6.6 TB |
  The us-east-1 SXM at $3.19/hr seen on 5 Sep is gone.
```

`rent-gpu-instance` needs a `gpu_type`, `region`, and `gpu_count` that match a live option exactly, so the agent has to list before it rents. You see the option and its price before you approve. Note the inventory moved in five days. The $3.19 SXM from the outline was gone, and the cheapest card was a $2.75 PCIe.

### 2. Rent one, with both gates firing

```
> rent the 1-GPU ca-east-1 one

⏺ Renting the 1x H100 PCIe in ca-east-1 at $2.75/hr.
⏺ mcp__hyperbolic-gpu__rent-gpu-instance(gpu_type: "h100", region: "ca-east-1", gpu_count: 1)
  Allow this tool call?  ❯ Yes  /  No
  ⎿ { "status": "pending", "rental": { "rental_id": 17917, "region": "ca-east-1",
       "label": "soft-apricot-ladybug", "created_at": "2026-09-10 12:25:47" } }

⏺ mcp__hyperbolic-gpu__list-user-instances()
  ⎿ rental 17917: Pending, no SSH yet
     ... (about three minutes later)
  ⎿ rental 17917: Running since 12:29:15, ssh -p 22 ubuntu@69.19.140.92

$ tail -1 ~/hyperbolic-guardrails/ledger.jsonl
{"rental_id":17917,"timer_pid":55006,"est_usd":1.75,"rented_at":"2026-09-10T12:30:31Z"}
```

Budget checked, then you were asked, then the call went out. Hyperbolic accepted the order in a second and the machine was running three and a half minutes later. The ledger row is the timer being armed.

One thing went wrong on this first run, and it is worth knowing. The original version of the rent tool waited for the machine to boot before returning. Claude Code gives a tool two minutes, then moves it to the background, and the timer hook received a response with no rental ID in it. The server now returns as soon as Hyperbolic accepts the rental, and the hook falls back to asking the API for the newest live rental if the response has none. A slow rent call is dangerous for another reason too. An agent that thinks the call failed will retry it, and now you have two GPUs.

### 4. Push past the cap and get blocked

```
> rent 8 more H100s in the same region

⏺ I'm going to hold on this one before placing it. The 8x H100 option costs
  $22/hr. Your balance is $5.00 with no overdraft allowed. Reply "go" and I'll
  place it anyway.

> go

⏺ mcp__hyperbolic-gpu__rent-gpu-instance(gpu_type: "h100", region: "ca-east-1", gpu_count: 8)
  ⎿ PreToolUse hook error: [guard.sh]: BLOCKED: renting 8x h100 in ca-east-1
     for up to 30 min is ~$14.00. Session total would be $15.75, cap is $10.

⏺ The order was blocked, not by Hyperbolic but by your own guardrail hook.
  Nothing was placed. I didn't route around the hook, for example by calling
  the v2 API directly. The cap is there to stop exactly this.
```

Two things happened here. Claude declined on its own first, because the balance could not cover it. That is nice, but it is a judgement call the model made and might not make next time. When told to go ahead, the hook refused before Claude Code could ask for approval. No prompt appeared. That is the guardrail, and it does not depend on the model's mood.

Manual first:

⏺ mcp__hyperbolic-gpu__ssh-disconnect()
⏺ mcp__hyperbolic-gpu__terminate-gpu-instance(rental_id: 17917, reason: "Done with nvidia-smi check")
  Allow this tool call?  ❯ Yes  /  No
  ⎿ { "status": "success", "message": "Rental successfully terminated",
       "started_at": "2026-09-10 12:29:15", "terminated_at": "2026-09-10T12:36:55Z" }

⏺ Rental 17917 is terminated. Ran for about 7.7 minutes, so the charge should
  be around $0.35.
```

The terminate hook found timer 55006 in the ledger and killed it, so nothing fires later against a rental that is already gone.

Then a second run with the window set to five minutes. Rent again, approve, and do nothing:

Five minutes after the rent call, the log shows the timer doing its job:

```
$ cat ~/hyperbolic-guardrails/ledger.jsonl.log
{"message":"Rental successfully terminated","rentalId":17918}

Hyperbolic's rental history agrees. Rental 17918 started at 13:01:35 and was terminated at 13:04:22. `list-user-instances` comes back empty. Nobody had to do anything.

**What the two runs cost.** Rental 17917 ran for 7.7 minutes and 17918 for 2.8 minutes, both at $2.75 an hour. The balance went from $5.00 to $4.65.
