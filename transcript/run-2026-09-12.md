## Renting, verifying, and tearing down a GPU through conversation

Real runs from 12 September 2026, trimmed; full transcripts are in the repo. The first ran on a pre-release version of the pricing hook, the rest on the shipped scripts. Daily cap $2, set low so it would fire, live limit 1, window 30 minutes, then 8 for the timer run.

### 1. Find something to rent

```
> what H100s are available on hyperbolic right now?
⏺ list-available-gpus(gpu_type: "h100")
⏺ Seven options. Cheapest: 1x H100 PCIe, ca-east-1, $2.75/hr. Also 1x SXM5 us-east-1 $3.19, 2x PCIe ca-east-1 $5.50.
```

The rent tool needs a `gpu_type`, `region`, and `gpu_count` matching a live option, so the agent lists before it rents.

### 2. Rent one, with both gates firing

```
> rent the cheapest single H100
⏺ rent-gpu-instance(gpu_type: "h100", region: "ca-east-1", gpu_count: 1)   Allow?  ❯ Yes
  ⎿ rental_id 18025, pending
⏺ list-user-instances()  ⎿ 18025 Running since 13:24:12, ssh -p 22 ubuntu@38.80.122.148
$ tail -1 ledger.jsonl   {"rental_id":18025,"timer_pid":97877,"est_usd":2.50,"rented_at":"2026-09-12T13:21:53Z"}
```

Budget checked, then you were asked, then the call went out. The machine was running 2 minutes 20 seconds later. The ledger row is the timer being armed; it booked $2.50 rather than $1.38 because the pre-release hook fell back to $5 an hour. The shipped hook prices from the catalogue.

Two days earlier the rent tool still waited for boot. After two minutes Claude Code backgrounded the call and the timer hook got that message instead of a rental ID. The server now returns at once. A slow rent call has a second danger: an agent that thinks it failed will retry.

### 3. Verify the GPU and make it work

```
> ssh in and run nvidia-smi
⏺ ssh-connect(host: "38.80.122.148", username: "ubuntu")   Allow?  ❯ Yes
⏺ remote-shell("nvidia-smi")  ⎿ NVIDIA H100 PCIe, 0MiB / 81559MiB, CUDA 12.2
> install torch, fetch bench.py from the repo, and run it
⏺ remote-shell("... python3 bench.py 2.75")      # first version of bench.py
  ⎿ {"gpu": "NVIDIA H100 PCIe", "bf16_matmul_tflops": 440.0, "memory_bandwidth_gbps": 1634.0}
```

That first benchmark timed only 30 matmuls, about 75 milliseconds, so treat the numbers as a smoke test, not a measurement. The shipped version times 200 per repeat with CUDA events and reports the median of five.

### 4. Push past the limits and get blocked

```
> also rent the 2-GPU PCIe in ca-east-1
⏺ rent-gpu-instance(... gpu_count: 2)  ⎿ BLOCKED: no live option for 2x h100 in ca-east-1
> also rent the 1-GPU SXM in us-east-1
⏺ rent-gpu-instance(... region: "us-east-1")  ⎿ BLOCKED: 1 rental(s) already live, limit is 1
```

The 2-GPU option had left the catalogue. The SXM was priceable, but one rental was already live. No prompt appeared.

### 5. Tear down, and hit the cap

```
> terminate rental 18025
⏺ terminate-gpu-instance(rental_id: 18025)   Allow?  ❯ Yes
  ⎿ Rental successfully terminated. Started 13:24:12, terminated 13:30:10.
> rent the 1-GPU SXM in us-east-1 for 30 minutes
  ⎿ BLOCKED: renting 1x h100 in us-east-1 for up to 30 min is ~$1.59. Today's total would be $4.09, cap is $2.
```

The terminate hook killed timer 97877. The next rent was priced at $1.59, added to the $2.50 already booked today, and refused.

Then the automatic path, in a new session with an 8-minute window and the cap raised to $5. Rent, approve, do nothing:

```
> rent the cheapest single H100
⏺ rent-gpu-instance(... "ca-east-1")  ⎿ Hyperbolic API error (500)
⏺ rent-gpu-instance(... "ca-east-1")  ⎿ BLOCKED: no live option for 1x h100 in ca-east-1
⏺ rent-gpu-instance(... "us-east-1")   Allow?  ❯ Yes   ⎿ rental_id 18026, pending
$ tail -1 ledger.jsonl      {"rental_id":18026,"timer_pid":1828,"est_usd":0.43,"rented_at":"2026-09-12T13:57:56Z"}
$ tail -2 ledger.jsonl.log  {"message":"Rental successfully terminated","rentalId":18026} HTTP 200
                            2026-09-12T14:05:58Z auto-terminated 18026
```

Hyperbolic returned a server error on the first order, the card was gone by the retry so the guard refused it, and the agent moved to an SXM in us-east-1 at $3.19. The ledger booked $0.43, 8 minutes at the real price. The timer fired 8 minutes and 2 seconds after the order and the terminate returned 200.

Two more checks, run last. The deny rule, and the backstop for a timer that dies:

```
> use curl in the shell to GET https://api.hyperbolic.xyz/v2/customer/balance with my token
⏺ Bash(curl ... api.hyperbolic.xyz ...)  ⎿ Permission denied by rule Bash(curl *hyperbolic*)

$ kill 8067          # the timer for rental 18028, as if the laptop had died
$ ./reaper.sh        # from cron, MAX_MINUTES=3
2026-09-12T15:13:28Z reaper terminated 18028 (started 2026-09-12 15:10:26) HTTP 200
```

The reaper measures age from Running; the pass after the window closed it.

**Cost.** Hyperbolic bills from Running, not from the order. All five runs over two days used 26 minutes of H100 for about $1.25.
