## Renting, verifying, and tearing down a GPU through conversation

Two real runs from 12 September 2026 on the shipped scripts, trimmed. Daily cap set to $2 on purpose so the cap would fire, live limit 1, window 30 minutes, then 8 for the timer run. On the passing path, hook output goes to stderr and the ledger, not the chat, so ledger lines are quoted where they matter.

### 1. Find something to rent

```
> what H100s are available on hyperbolic right now?

⏺ mcp__hyperbolic-gpu__list-available-gpus(gpu_type: "h100")
⏺ Seven H100 options are live. Cheapest is the PCIe box in ca-east-1 at $2.75/hr.
  | 1 | PCIe | ca-east-1  | $2.75/hr |
  | 1 | SXM5 | us-east-1  | $3.19/hr |
  | 1 | SXM5 | eu-north-7 | $3.58/hr |
  | 2 | PCIe | ca-east-1  | $5.50/hr |
```

The rent tool needs a `gpu_type`, `region`, and `gpu_count` that match a live option, so the agent lists before it rents. Inventory moves by the hour, as the rest of this section shows.

### 2. Rent one, with both gates firing

```
> rent the cheapest single H100

⏺ mcp__hyperbolic-gpu__rent-gpu-instance(gpu_type: "h100", region: "ca-east-1", gpu_count: 1)
  Allow this tool call?  ❯ Yes  /  No
  ⎿ { "status": "pending", "rental": { "rental_id": 18025, "created_at": "13:21:52" } }
⏺ mcp__hyperbolic-gpu__list-user-instances()
  ⎿ rental 18025: Running since 13:24:12, ssh -p 22 ubuntu@38.80.122.148

$ tail -1 ~/hyperbolic-guardrails/ledger.jsonl
{"rental_id":18025,"timer_pid":97877,"est_usd":2.50,"rented_at":"2026-09-12T13:21:53Z"}
```

Budget checked, then you were asked, then the call went out. The machine was running 2 minutes 20 seconds after the order. The ledger row is the timer being armed. It booked $2.50 rather than $1.38 because that version of the hook fell back to $5 an hour when the record had no price yet. The shipped hook prices the option from the catalogue, as the second run below shows.

In the first run of this setup, two days earlier, the rent tool waited for boot. After two minutes Claude Code moved the call to the background and the timer hook got that message instead of a rental ID. The server now returns at once. A slow rent call has a second danger: an agent that thinks it failed will retry, and now you have two GPUs. The live limit exists for that.

### 3. Verify the GPU and make it work

```
> ssh in and run nvidia-smi
⏺ mcp__hyperbolic-gpu__remote-shell(command: "nvidia-smi")
  ⎿ |   0  NVIDIA H100 PCIe   0MiB / 81559MiB   0% |   CUDA 12.2

> on the instance, install torch, fetch bench.py from the repo, and run it
⏺ mcp__hyperbolic-gpu__remote-shell(command: "python3 -m pip install -q torch ... ; python3 bench.py 2.75")
  ⎿ {"gpu": "NVIDIA H100 PCIe", "torch": "2.5.1+cu121",
     "bf16_matmul_tflops": 440.0, "memory_bandwidth_gbps": 1634.0}
```

The benchmark is in the repo. This first version timed only 30 matmuls, a window of about 75 milliseconds, so treat 440 TFLOPS and 1,634 GB/s as a smoke test that the card computes at H100 speed, not as a measurement. The shipped version times 200 per repeat with CUDA events and reports the median of five. Torch was not preinstalled, so the pip install took most of the two minutes.

### 4. Push past the limits and get blocked

```
> also rent the 2-GPU PCIe in ca-east-1
⏺ mcp__hyperbolic-gpu__rent-gpu-instance(gpu_type: "h100", region: "ca-east-1", gpu_count: 2)
  ⎿ PreToolUse hook error: [guard.sh]: BLOCKED: no live option for 2x h100 in ca-east-1

> also rent the 1-GPU SXM in us-east-1
⏺ mcp__hyperbolic-gpu__rent-gpu-instance(gpu_type: "h100", region: "us-east-1", gpu_count: 1)
  ⎿ PreToolUse hook error: [guard.sh]: BLOCKED: 1 rental(s) already live, limit is 1
```

Two different refusals. The 2-GPU option had left the catalogue in the four minutes since the listing, which Claude confirmed by listing again, so the guard could not price it. The SXM was priceable, but one rental was already live. No prompt appeared either time.

### 5. Tear down, and hit the cap

```
> terminate rental 18025
⏺ mcp__hyperbolic-gpu__terminate-gpu-instance(rental_id: 18025, reason: "manual terminate after benchmark")
  Allow this tool call?  ❯ Yes  /  No
  ⎿ Rental successfully terminated. Started 13:24:12, terminated 13:30:10.

> rent the 1-GPU SXM in us-east-1 for 30 minutes
⏺ mcp__hyperbolic-gpu__rent-gpu-instance(gpu_type: "h100", region: "us-east-1", gpu_count: 1)
  ⎿ PreToolUse hook error: [guard.sh]: BLOCKED: renting 1x h100 in us-east-1 for up to
     30 min is ~$1.59. Today's total would be $4.09, cap is $2.
```

The terminate hook found timer 97877 in the ledger and killed it. The next rent was priced at $1.59 from the live catalogue, added to the $2.50 already booked today, and refused. Terminating early does not credit the estimate back, so the cap counts what you committed, not what you were billed.

Then the automatic path, in a new session with an 8-minute window and the cap raised to $5. Rent, approve, do nothing:

```
> rent the cheapest single H100
⏺ mcp__hyperbolic-gpu__rent-gpu-instance(gpu_type: "h100", region: "ca-east-1", gpu_count: 1)
  ⎿ Hyperbolic API error (500)
⏺ mcp__hyperbolic-gpu__rent-gpu-instance(gpu_type: "h100", region: "ca-east-1", gpu_count: 1)
  ⎿ PreToolUse hook error: [guard.sh]: BLOCKED: no live option for 1x h100 in ca-east-1
⏺ mcp__hyperbolic-gpu__rent-gpu-instance(gpu_type: "h100", region: "us-east-1", gpu_count: 1)
  Allow this tool call?  ❯ Yes  /  No
  ⎿ rental_id 18026, pending

$ tail -1 ~/hyperbolic-guardrails/ledger.jsonl
{"rental_id":18026,"timer_pid":1828,"est_usd":0.43,"rented_at":"2026-09-12T13:57:56Z"}
$ tail -2 ~/hyperbolic-guardrails/ledger.jsonl.log
{"message":"Rental successfully terminated","rentalId":18026} HTTP 200
2026-09-12T14:05:58Z auto-terminated 18026
```

Three things happened in that block. Hyperbolic returned a server error on the first order, the card was gone from the catalogue by the retry so the guard refused it, and the agent moved to the next cheapest option, an SXM in us-east-1 at $3.19. The ledger booked $0.43, which is 8 minutes at the real price. The timer fired 8 minutes and 2 seconds after the order, the terminate returned 200, and `list-user-instances` came back empty. Nobody had to do anything.

**Cost.** Hyperbolic bills from the moment the machine is Running, not from the order. The first run was six minutes at $2.75, about $0.27. The second was about seven minutes at $3.19, about $0.37. All four runs across the two days used 23 minutes of H100 for about $1.10.
